## 1. Purpose

This document defines the requirements for features added by our fork of LibreChat v0.8.4. These are additive features — they do not modify upstream behavior when disabled. The fork is deployed as `henson-librechat` in the Joshua26 ecosystem on M5.

---

## 2. Scope

Three features:

1. **Default-Enabled MCP Toggle** — allow admins to mark MCP servers as default-enabled for new chats
2. **Proactive Context Compaction** — automatic and manual context window management for agents
3. **File Browser Panel** — browsable filesystem panel with path insertion into prompts

All changes are scoped to our fork. No upstream LibreChat files are modified in ways that would conflict with future upstream merges, except where additive hooks are required.

---

## 3. Feature 1: Default-Enabled MCP Toggle

### 3.1 User Stories

- As an admin, I want to mark specific MCP servers as "default enabled" so that new chat sessions automatically have those servers active without manual selection each time.
- As a user, I want my new chats to have the commonly-used MCP tools already selected so I don't have to toggle them on every time.

### 3.2 Functional Requirements

| ID | Requirement |
|---|---|
| F1.1 | Each MCP server card in the MCP Settings panel has a toggle switch labeled "Enable by default in new chats" |
| F1.2 | Toggle state is persisted in browser localStorage per user |
| F1.3 | When a new non-agent chat is started, all default-enabled servers are automatically selected in the ephemeral MCP picker |
| F1.4 | The default selection does NOT apply to agent conversations — agents use their own configured MCP tools |
| F1.5 | Toggling defaults does not affect existing conversations |
| F1.6 | Default state survives page reload |

### 3.3 Acceptance Criteria

- Toggle a server as default-enabled, start a new chat, verify the server is auto-selected
- Untoggle, start a new chat, verify the server is not selected
- Start an agent conversation, verify the agent uses its own MCP tools regardless of default settings
- Reload the page, verify default settings are preserved

## 4. Feature 2: Proactive Context Compaction

### 4.1 User Stories

- As an agent creator, I want to enable automatic context compaction so long-running conversations don't silently lose context when the window fills.
- As a user, I want to type `/compact` to manually trigger context compaction when I feel the conversation is getting too long.
- As an agent creator, I want to configure the compaction threshold (percentage of context window) that triggers automatic compaction.

### 4.2 Functional Requirements — Auto Compact

| ID | Requirement |
|---|---|
| F2.1 | Agent Advanced settings panel has an "Auto Compact" toggle (boolean, default false) |
| F2.2 | When Auto Compact is enabled, a "Compact Threshold (%)" number input appears (default 80, range 10-99) |
| F2.3 | `auto_compact` and `compact_threshold` are persisted on the agent document in MongoDB |
| F2.4 | When the agent's context token count exceeds `compact_threshold`% of `maxContextTokens`, the oldest messages (all but the newest 10% of the window) are summarized |
| F2.5 | The summary targets 5% of the context window token budget |
| F2.6 | The summary is generated by calling the agent's own configured model |
| F2.7 | After compaction: ~5% summary + ~10% raw = ~15% used, ~85% free |
| F2.8 | The summary is stored on the oldest message's `summary` field in MongoDB |
| F2.9 | On subsequent requests, if a stored summary exists it is prepended to the context instead of re-summarizing |

### 4.3 Functional Requirements — Manual Compact

| ID | Requirement |
|---|---|
| F2.10 | User types `/compact` in the chat prompt input and presses Enter |
| F2.11 | The `/compact` text is intercepted before reaching the model — no message is sent to the LLM |
| F2.12 | A POST request is made to `/api/convos/:conversationId/compact` |
| F2.13 | The endpoint summarizes the oldest 70% of messages in the conversation |
| F2.14 | The summary is stored on the oldest message's `summary` field |
| F2.15 | The user receives visual feedback (toast notification) indicating success or failure |
| F2.16 | The manual compact endpoint uses the app-level OpenAI key and a configurable model (env `COMPACT_MODEL`, default `gpt-4o-mini`) |

### 4.4 Acceptance Criteria

- Create an agent with auto_compact=true, compact_threshold=80 — verify fields persist in DB
- Toggle auto_compact on from the Advanced panel, save, reload — verify it persists
- Send enough messages to exceed the threshold — verify summarization fires
- Type `/compact` in an existing conversation — verify toast feedback and summary written to DB
- Verify the agent can use MCP tools before and after compaction (no regression)

## 5. Feature 3: File Browser Panel

### 5.1 User Stories

- As a user, I want to browse the container's mounted filesystem from within LibreChat so I can reference file paths in my prompts without guessing or remembering them.
- As a user, I want to insert a file or folder path into my prompt with a single click so the agent knows exactly what to work with.
- As a user, I want to double-click a file to preview or download it directly from the browser.

### 5.2 Functional Requirements

| ID | Requirement |
|---|---|
| F3.1 | A "File Browser" button appears in the right-hand control panel (alongside Agent Builder, Prompts, Memories, MCP Settings) |
| F3.2 | The panel is only visible when `interface.fileBrowser: true` is set in `librechat.yaml` — default is `false` (opt-in) |
| F3.3 | When opened, the panel shows the container's configured mount points as root nodes in a collapsible tree |
| F3.4 | Single click on a folder expands or collapses it, showing its children |
| F3.5 | Single click on a file selects it (visual highlight) |
| F3.6 | An "Insert Path" button in the panel's top bar is disabled/gray until a file or folder is selected |
| F3.7 | Clicking "Insert Path" pastes the full absolute path of the selected item into the prompt textarea at the cursor position |
| F3.8 | Double-click on a file opens viewable types (images, PDF, text, HTML) in a new browser tab |
| F3.9 | Double-click on non-viewable file types triggers a browser download |
| F3.10 | Backend: new Express endpoint `GET /api/files/browse?path=...` returns directory listing as JSON (name, type, size, modified) |
| F3.11 | Backend: new Express endpoint `GET /api/files/browse/content?path=...` serves raw file content with appropriate Content-Type header |
| F3.12 | Both endpoints validate that the requested path is within configured allowed directories |
| F3.13 | The allowed directories for the file browser are configured in `librechat.yaml` under `interface.fileBrowserPaths` (array of absolute paths) |

### 5.3 Acceptance Criteria

- Set `interface.fileBrowser: true` in config, verify panel button appears
- Set `interface.fileBrowser: false`, verify panel button is hidden
- Open panel, verify mount points appear as root nodes
- Expand a folder, verify children load
- Select a file, verify Insert Path button becomes active
- Click Insert Path, verify path appears in prompt textarea
- Double-click an image file, verify it opens in a new tab
- Double-click a binary file, verify download triggers
- Request a path outside allowed directories, verify 403 error

## 7. Known Constraints

1. **Fork of upstream** — all changes must be additive. Minimize modifications to existing upstream files. Prefer new files and hooks.
2. **Container deployment** — the fork runs as `henson-librechat` in Docker on M5. Dockerfile must rebuild all TypeScript packages (`data-provider`, `data-schemas`, `api`) from source since `dist` is excluded from the Docker build context.
3. **No Node workspace testing** — Jest tests in the `api` workspace fail due to dependency resolution issues. All testing uses Python scripts hitting the deployed container and Malory browser automation.
4. **MCP tool format** — MCP tool names follow the format `toolName_mcp_serverName` (server name comes LAST after the `_mcp_` delimiter).
5. **Agent MCP tools** — agents get MCP tools from their own configuration via `extractMCPServers(agent)`, not from the ephemeral per-chat MCP picker. The ephemeral picker is hidden for agent endpoints.
